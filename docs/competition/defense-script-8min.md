# Sentinel-Guardian 8 分钟答辩稿

## 开场：40 秒

各位老师好，我们的项目是 Sentinel-Guardian，一个面向企业智能体上线前安全审计与
自动加固的安全审计智能体。

用户只需要提交 Agent 的源码、配置或运行入口，并提出“审计这个 Agent 是否可以
上线”。Sentinel-Guardian 会自主理解资产、制定测试计划、执行攻击、分析轨迹、
定位风险、生成防御并完成复测，最后给出带证据的上线建议。

## 问题背景：60 秒

企业 Agent 已经不只是聊天模型。它会检索资料、读取文件、访问网络、运行代码、
写入记忆并改变业务状态。传统 LLM 测试只比较输入和最终回答，很难发现工具参数、
权限边界和状态变化中的风险。

人工红队还面临三个问题：固定样本容易漏测；模型拒答、环境失败和安全拦截容易混淆；
防御可能通过过度拒绝降低攻击成功率，却同时破坏正常业务。因此企业缺少一种能够
自动完成上线前安全验收、并给出可追溯证据的智能体。

## 完整任务：60 秒

Sentinel-Guardian 执行十个步骤：

```text
解析源码与配置
 -> 识别工具、权限和风险面
 -> 制定安全测试计划
 -> 生成针对性攻击
 -> 在隔离环境真实执行
 -> 分析轨迹和攻击效果
 -> 定位风险节点
 -> 生成防御策略
 -> 自动回归验证
 -> 输出上线建议和证据报告
```

最终决策分为允许上线、修复后复测、高风险禁止上线和需要人工审批四种。

## 系统方案：100 秒

系统由三个智能体、统一运行时和证据层组成。

Attack Agent 根据 AgentProfile、工具权限和历史失败轨迹生成攻击候选。攻击失败后，
它会基于证据反思和调整策略，而不是只重复固定 payload。

Evaluation Agent 观察 LLM 输入输出、工具调用、文件和网络访问、Guard decision、
finish/error 等事件，通过确定性 Oracle 和轨迹信号判断攻击是否产生真实效果，并把
风险定位到具体节点。

Defense Agent 根据风险节点生成局部 Guard，在同一模型、case、seed 和预算下复测，
同时检查 ASR、FPR、clean utility 和成本，防止“一刀切”防御。

LLM 负责理解材料、规划候选和解释决策；schema、权限规则和确定性 Oracle 负责边界
校验与安全兜底。所有结果写入 manifest、provenance、原始 trajectory 和 evidence
index。

## 演示案例：90 秒

演示对象是一个企业知识助手。它的正常任务是检索公开文档、读取授权文件并生成摘要，
同时具备 Browser、文件和 Python 工具。

Sentinel-Guardian 首先识别这些高权限工具并生成结构化测试计划。随后执行提示注入、
敏感文件读取、路径穿越、SSRF 和工具滥用测试。系统展示攻击所经过的 LLM 与工具
轨迹、产生的真实 effect marker、命中的风险节点和证据引用。

发现风险后，Defense Agent 只在对应工具或协议节点安装 Guard，再重放相同攻击和正常
任务。评委可以直接看到攻击是否被阻断、正常摘要任务是否仍然成功，以及最终上线
决策为何发生变化。

## 当前证据：90 秒

离线演示可以通过以下命令复现：

```bash
redsentinel demo --output-dir artifacts --seed 42
```

离线配对 smoke 为 3/3、FPR 为 0；协同进化 smoke 的 ASR 从 43.75% 下降到 0%，
覆盖 7 轮；当前默认全量测试为 1038 passed、2 deselected。离线 smoke 只用于证明工程和算法链路，
不作为真实 Agent 效果。

真实 OpenManus W2 rerun10 完成了 15/15 次容器运行，runtime failure 为 0%。
五个适用 baseline 均产生注册攻击效果，五个 guarded 运行均成功阻断；baseline ASR
为 100%，guarded ASR 为 0%，clean utility 为 100%，FPR 为 0%。

这个结果的边界是单 Agent、单模型、单 seed。OpenManus 缺少等价邮件工具，因此
邮件外传场景标记为不适用，适用覆盖为 5/6。

## 差异化与路线：60 秒

Sentinel-Guardian 的差异不在于再做一个普通问答 Agent，而是让智能体自主完成另一个
智能体的安全验收。它同时展示复杂任务理解、结构化规划、运行环境感知、多智能体决策、
工具行动、数据分析和实际业务判断。

当前底层画像、攻击、评测、防御、复测和报告能力已经存在。后续全部开发只服务本次
比赛：依次完成统一审计任务入口、可观察的结构化计划、四态上线决策、企业知识助手
案例和稳定的现场演示，不再推进独立论文或跨 Agent 实验路线。

## 边界与收尾：20 秒

所有攻击只作用于授权、本地或明确隔离的环境。自动建议不会绕过企业现有人工审批。
Sentinel-Guardian 的目标是让 Agent 上线安全验收从一次性人工检查，变成可执行、
可复测、可追溯的智能体任务。
