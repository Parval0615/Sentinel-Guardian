# Sentinel Guardian 闭环 Demo 录制指南

## 录制口径

- 通用 Docker 镜像：系统真实完成上传、摘要校验、静态画像、攻击规划、防护策略挂载、前后复测与证据留存；执行阶段使用本地可复现实验运行器。
- OpenManus 镜像：画像识别为 OpenManus 后自动切换真实运行模式，录制前必须完成 Docker、OpenManus 镜像和三角色模型连接预检。
- 不要把通用镜像的本地可复现实验描述为“原容器真实业务执行”。

## 录制前检查

1. 启动根目录 `Sentinel Guardian.app`，确认右上角显示“审计服务在线”。
2. 准备由 `docker save` 导出的 `.tar` 文件；镜像需包含有效的 `manifest.json`、配置文件和层文件。
3. 使用固定账号、固定镜像和随机种子 `42`，保证多次录制结果一致。
4. OpenManus 真实运行还需在“模型配置”中完成被测、攻击、防御三个模型的连接测试。

## 推荐录制流程

### 1. 上传 Agent

进入“Agent 资产”，点击“接入镜像”，选择 `.tar` 文件并开始导入。

讲解重点：

- 系统从 Docker archive 自动读取镜像身份，不依赖文件名猜测 Agent。
- 镜像仅属于当前登录用户。
- 入口识别失败时才要求开发人员补充 Python 运行模块。

画面验收：

- 上传进度完成。
- 画像构建依次经过清单读取、解包、静态提取、框架识别、图谱重建、语义增强、动态验证、发布八个阶段。
- 完成后资产列表出现新 Agent。

### 2. 查看静态画像

打开新 Agent，展示“镜像与画像身份”、框架、能力、权限、安全控制、风险路径和证据索引。

讲解重点：

- 审计绑定镜像摘要、画像 ID 和画像 SHA-256，后续无法静默替换输入。
- 风险路径会成为攻击集生成与预测攻击节点的依据。
- OpenManus 被识别后会自动进入真实运行预检流程。

### 3. 生成并审阅第一次攻击集

点击“发起审计”，确认 Agent，点击“填入示例”，再点击“生成攻击集”。

讲解重点：

- 建议不会强制覆盖用户输入，必须由用户主动采用。
- 正常业务任务用于验证防护没有破坏业务能力。
- 攻击集生成后不会立即执行，必须人工核对风险范围、预测节点和证据要求。

画面验收：

- “确认正式审计范围”页面显示攻击数量、画像版本和计划来源。
- 运行环境预检全部就绪。
- 勾选授权后才能执行。

### 4. 第一次审计与防御挂载

批准执行，展示阶段时间线：画像分析、攻击规划、基线攻击、防护生成、防护复测、结论生成。

报告页先展示防护前后攻击成功率和业务效用，再滚动到“防护方案”。

讲解重点：

- 首次攻击记录防护前失效节点。
- 系统根据失效证据生成最小防护策略。
- 防护策略写入隔离审计沙箱并产生安装编号、策略文件和 SHA-256 校验。
- 防护后复测使用相同源码快照、攻击基准和随机种子。

画面验收：

- 显示“防护已挂载并用于本轮复测”。
- “查看防护挂载凭据”可展开查看安装与校验证据。
- 攻击矩阵显示每个场景的防护前、防护后结果及实际挂载的防御。

### 5. 第二次审计

点击“生成第 2 轮攻击集”。

讲解重点：

- 第二轮不是复制第一轮，而是根据上一轮防护后结果和失效反馈生成。
- 第二轮仍经过运行预检、攻击集审阅和人工授权，不能绕过安全门禁。

画面验收：

- 审阅页明确显示“根据上一轮失效反馈生成”和“计划来源：上一轮失效反馈”。
- 完成后报告标题显示“第 2 轮”。
- 攻击矩阵来源显示“上一轮结果反馈生成”。
- 第二轮同样展示防御挂载状态、复测结果和完整证据链。

## 收尾镜头

停留在第二轮报告顶部，依次指出：

1. 第 2 轮标识。
2. 防护前后攻击成功率变化。
3. 正常业务能力是否保持。
4. 攻击矩阵来源为上一轮反馈。
5. 防护挂载凭据和证据完整性。
